# AI 流式停顿调查（2026-11-01）

## 已确认的根因

ChatGPT Responses 适配器在 `Flux.create` 中阻塞读取 HTTP 响应，再调用默认的 `subscribeOn(boundedElastic())`。默认调度也把下游补充数据请求排入同一个工作线程；该线程尚在读取模型输出，因此这些请求要等到上游完成才能执行。

Copilot 和文档翻译都通过 `ChatClient.stream().content().toIterable()` 消费流。最初请求的 256 个片段耗尽后，后续片段继续被适配器读入缓冲，却不能及时交付给控制器。模型结束后，积压内容才一次性交付。

真实连接的公开合成文本测试记录如下，不包含课程材料、API 密钥、令牌或生成正文：

| 指标 | 修复前 |
| --- | --- |
| 翻译模式 | ChatGPT |
| 总输出 | 4,266 个字符、3,097 个片段 |
| 第一个片段 | 3,075 ms |
| 第 256 → 257 个片段间隔 | **51,837 ms** |
| 第 257 个片段 | 59,480 ms |
| 全部完成 | 59,513 ms |

片段时间原始数据位于 `.run/ai-stream-before.json`。

## 修复与回归证据

适配器改为 `subscribeOn(boundedElastic(), false)`，让补充数据请求不再排在阻塞的 HTTP 读取任务之后。这不是增大缓冲区，也没有延迟到最终文本才渲染。

[Reactor 官方文档](https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Flux.html#subscribeOn(reactor.core.scheduler.Scheduler,boolean))明确说明，阻塞的 `create` 应使用此调度方式，以免请求堆积在发射任务后。

`ChatGptResponsesModelTest.keepsDeliveringPastPrefetchBoundaryBeforeUpstreamCompletes` 启动本地真实 HTTP SSE 源，发送 320 个片段，并等待消费者确认收到第 257 个片段后才结束响应。旧实现此断言失败；修改后通过。它经过实际 `ChatClient.stream().content().toIterable()` 调用路径。

`ApiKeyStreamingTest.apiKeyStreamAlsoDeliversBeyond256BeforeCompletion` 对 API Key 路径独立执行相同边界检查，结果通过；没有把该路径无依据地替换为 ChatGPT 适配器。

完整后端回归：43 项通过。

## 前端与代理

另用独立本地 SSE 服务每 30 ms 发出一段含 Markdown 和公式的公开测试文字，共 300 段，测量应用翻译区实际 DOM 更新。

- 修复前前端基线：110 次更新，最长更新间隔 269 ms，最长主线程任务 246 ms。
- 翻译区按动画帧合并状态更新后：113 次更新，最长间隔 341 ms，最长主线程任务 243 ms。
- 该压力场景仍存在约 0.3 秒的长文本/公式渲染峰值，不能声称这部分性能已显著提升；它没有复现真实连接中的 51.8 秒固定边界停顿。
- 原始长停顿在不经过浏览器和 Vite 代理的 Java 客户端中已出现，且本地上游也能复现，因此代理和浏览器不是这个固定 256 片段故障的必要条件。

## 翻译缓存与标题

- 当前文档预览会话内，按文档 ID、页码、目标语言缓存译文。
- 翻页再返回直接恢复缓存，不自动重新请求模型。
- 生成过程中翻到其他页，后续片段仍写入原页缓存，不污染当前页。
- 已有译文时，“翻译文本”提示标题淡出。
- 浏览器回归验证：生成中翻页、完成后返回、切换语言再切回，正文恢复正确，总翻译请求数仍为 1。

## 实际服务复测的限制

修复后的真实复测发现当前账号配置已从 ChatGPT 改为 DeepSeek API。该次请求在 TLS 握手阶段出现 EOF，未收到输出片段，因此不能据此声明修复后的真实模型生成已验证成功。未改动用户的模型配置，也未更换模型或降级协议。

已完成的证据是：真实 ChatGPT 路径复现、同调用链本地回归先失败后通过、API Key 独立边界验证、前端持续流与缓存回归。DeepSeek 的真实网络生成仍需在其连接可用后验证。

## 翻译框整段显示的后续排查（2026-11-01）

当前 DeepSeek API 纯文本实测成功：2423 个片段、3648 字符，约 28 秒持续返回；此前 TLS 失败不代表当前连接状态。合成图片请求被服务端拒绝，不能用纯文本结果声明完整图片翻译链路已经验证。

移除翻译框新加的 requestAnimationFrame 调度，收到 delta 时直接更新当前页的 React 状态，同时继续写入按页和语言隔离的缓存。在刻意暂停动画帧回调、网络流仍逐段返回的浏览器测试中，修改前首段直到请求结束才出现；修改后 500ms 内显示首段，1.8 秒后显示完整内容。缓存、生成时翻页、返回原页及语言隔离测试也通过。该测试证明翻译显示不再依赖动画帧回调，不等同于已经复现用户 Safari 的原始触发原因。
